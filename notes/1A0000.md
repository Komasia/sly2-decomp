# Notes for 0x1A0000-0x1B0000

## Techniques that mattered here
- **Constructors with an unknown func_ name**: write real C++ and give the ctor an asm label inside the class:
  `struct CDer : CBase { ...; CDer() __asm__("func_001ADDF0"); virtual void f(); };` and declare the base ctor
  the same way (`CBase() __asm__("func_001DA728");`). g++ then emits base-ctor call, vptr store, body in the
  original order/registers (func_001ADDF0 only matched this way; the C version had v0/v1 swapped).
- Virtual call whose result is returned (`return e->pfn(...)`) allocates vt in $v1 / pfn in $v0; a void call
  gives vt in $v0 / pfn in $v1 (func_001A2358). Pick return type by register pattern.
- `if ((v ^ 1) & 1)` gives `xori; andi; beqz` (tagged-pointer test, func_001A66C8/001A66F8);
  `!(v & 1)` gives andi/bnez and `~v & 1` gives nor.
- Switch trees: the pivot constants reveal phantom cases. func_001A2160 matched only with an extra `case 4: break;`;
  `n==2||n==3` written as `switch (n) { case 2: case 3: ... }` gives the slti 4 / slti 2 form (func_001ACC38).
- Reading g_clock+0x3C through a struct (`struct CLOCK {..; float t3c;} D_002DDED0; D_002DDED0.t3c`) instead of
  `extern float D_002DDF0C` changed scheduling to the target's (func_001ACC38).

### Toolchain issue (new, precise): nop padding before div.s at slot 1 of a basic block
- Round 6 inserts 2 nops when div.s/sqrt.s starts a block. The original assembler's rule is more general: div.s must have
  **at least two instructions before it in its basic block**; if the block has only one instruction before the div,
  ONE nop is inserted. Evidence from asm/text.s (block = after label / branch delay slot): `sub.s; nop; div.s` at
  0x11D0C0, 0x14AB98, 0x14ACC0, 0x196A4C, 0x1A3798; `lwc1; nop; div.s` at 0x11F124, 0x11FFF8, 0x138540, 0x138740,
  0x175A2C, 0x1761C8, 0x1D4348, 0x20C4EC, 0x220260; `c.lt.s; nop; div.s` at 0x1BC7E4. Blocks with 2+ instructions
  before the div (`lwc1 sub.s div.s`, `sub.s sub.s div.s`, `lw lwc1 div.s`) get no nop.
- FitLinearFunction__FffffPfT4 (build/hand_wip) is exactly this: block = `sub.s $f2; div.s` at the beql target,
  target has one nop in between. Verified: adding a single `nop` before the division makes it MATCH (hack not kept).
  The functions containing the other addresses above are probably blocked the same way.

- **GS DISPLAY registers (D_002DEB80+0x18 / +0x40) are bitfield structs with `unsigned int` fields in an 8-aligned struct**:
  `struct { unsigned int dx:12, dy:11, r0:9; unsigned int r1; } __attribute__((aligned(8)))`. Chained
  `p->d1.dx = p->d2.dx = D_002F6468;` (float) reproduces the target's ld/and/or/sd with the duplicated `daddu` copy
  (func_001AF6D0); reads `(float)p->d1.dx` give the lw + unsigned->float sequence (func_001AEAA8).
- func_001AEAA8 (SetState of a menu object, vt slots 10/11 on leave-0/enter-0; old-state switch needs phantom
  `case 1: case 11: break;` to get the 12-entry table): entry lookup `*(int *)((char *)pe->x4 + (pe->x14 << 5))` was
  the only form giving the target's addu operand order.
- **CRef-returning calls (func_002581C0 etc.) must be C++ with a non-trivial CRef**: declare
  `struct CRef { int m_tagk; T m_tag; CRef(const CRef &) __asm__("func_001291A8"); ~CRef() { func_00129EC8(this); } };`
  The copy-ctor declaration is what makes g++ return it through the hidden pointer (without it an 8-byte CRef comes back
  in $v0). NOTE: an in-class `~CRef() __asm__("...")` declaration is silently dropped by g++ 2.95 (no dtor call emitted) -
  always use an inline dtor that calls the extern "C" function. Same for other dtors (e.g. `~T() { func_001AE4A0(this, 2); }`,
  the 2 is g++'s in-charge arg).
- Value fetch as `static inline float GetF(int k, void *p) { return Eval(k, p).m_tag; }` with `CRef Eval(int, void*)
  __asm__("func_002581C0")` reproduces "hidden ptr = addiu a0,sp,X each time, dtor ptr hoisted to an s-reg" (func_001AD538,
  func_001AB418). A loop writing `a[i] = GetF(...)` with `pb++` was the only form with the right s-reg order.
- **Ternary vs if/else after a CRef temp** (func_001AF9C8): `*s = GetTag(x) ? A : B` gives movn; the target's
  branchy `v=A; beqz; v=B; sw` form comes from `if (GetTag(x)) *s = A; else *s = B;`. Inner `switch` on the tag needed a
  phantom `case 0:` sharing the default label for the target's `beq 1 / slti 2 / beq 2` tree.
- **Thread-start PMF argument** (func_001AAF90(void *, PMF)): pass a real C++ pointer-to-member `&X::A` with
  `struct X { int A() __asm__("func_001AB0A0"); }` and `void StartThread(void *, int (X::*)()) __asm__("func_001AAF90");`
  - g++ then loads the {0,-1,fn} constant with ldl/ldr straight into a1 like the target (a struct PMF goes via the stack).
- func_001AB1A0: `func_001AB418(s, s->xC)` is SetState(s, stateNew) - the a1 load before the branch revealed the 2nd arg;
  final `if (0.3f <= t - s->x10) {...}` positive form gave c.le/bc1f.

### Unsolved CRef-call pattern (func_001ACFE0, func_001AFB88 and probably more)
Target for `D_003E0FE4->Fn(<copy of ref>, D_003D4A60)` where Fn = func_00258200 returns CRef:
`lw s0,D_003E0FE4` (this, BEFORE the copy) ; ref fields stored at sp+0 ; `jal func_001291A8(a0=sp+0x10, a1=sp)` ;
`jal Fn(a0=sp+0x20, a1=s0, a2=sp+0x10, a3)` ; dtors sp+0x20, sp+0x10, sp+0 - with every sp+X address rematerialised.
Findings (mini test files compiled with -S): g++ 2.95 does NOT destroy by-value arguments in the caller, so the 3 caller
dtors mean Fn takes `const CRef &` and the source made an explicit copy (`Fn(CRef(ref))` or an inline wrapper with a
by-value CRef param). `O *po = D_003E0FE4;` before `CRef ref(...)` + `po->Fn(CRef(ref), ...)` gets this-first and the slot
order, but the copy's address lands in an s-reg (target: constants). `static inline void Send(CRef r) { D_003E0FE4->Fn(r,..); }`
gets slots + s-regs elsewhere right but loads `this` after the copy (func_001ACFE0 wip, 13 diffs).
