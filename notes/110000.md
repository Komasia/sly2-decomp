## Systemic problems (tool/assembler limitations) -> build/hand_wip
- **Original assembler != our as.exe.** Evidence:
  1. FP hazard nops: original inserts a `nop` between `mtc1 rX,$fN` and an immediately following use of $fN, between
     `c.cond.s` and `bc1t/bc1f` emitted in reorder mode (unfilled delay slot), and after FP ops feeding div/sqrt.
     Ours doesn't -> func_0011D898, func_0011CF60, GLimitLm__FP2LMf, func_0011DCD8, func_0011D508 are code-identical except these nops.
  2. `dli 0xfff0000000000000` is expanded by the original as `addiu -1; dsll32 20`, ours as `ori 0xfff0; dsll32 16`
     (GTrunc__Fd otherwise close).
  3. Short-loop padding also applies to loops containing a `jal` or inner branches (func_00112B30, func_0011A118,
     func_00117FD0); tools/asfix.py skips those loops.
- **Factory/new functions** (0x110CD0.., 0x111588, 0x113060, 0x113708, 0x113840, 0x111E40.., ~60 functions):
  `p = new(cb); p->vt@0xC = X; p->0 = p->4 = 0; [member ctors]`. Target allocates the vtable address into $v1
  (sched1 put the lui before `daddu s0,v0`), we always get $v0. Tried C inline ctors, real C++ `new` with classes,
  class operator new, inline alloc wrapper, all store orders. Not solved. (func_00112B30, where zero stores come
  first, does get the right registers.)
- func_00110680 / func_001104F0 (RefSetArgsFromSplice wrappers: `CRef f(pv, c, CRef *aref)` with local `int aotype[N] = {..}`)
  are exact except the struct-copy of the OTYPE initializer is scheduled before the arg setup.
- DecomposeRotateMatrixPanTilt: sqrt.s source register (f1 vs f13) and atan2 arg load order differ.
- __ml__FRC7MATRIX4G8VU_FLOAT: with NRV (`return matRet`) only the result pointer register differs ($v0 vs $a0).
- func_0011E1A0 (VU_VECTOR from sincos via pextlw/pcpyld): register allocation of inline asm operands differs.
- func_00117030 starts with two nops in the target (alignment/junk?); body is a cubic Hermite evaluation.

## Round 4
Matched (24): func_00110CD0, 00110D18, 00110D60, 00110EC0, 00111090, 00111218, 00111260, 001112A8, 001112F0,
00111338, 00111380 (factories), func_0011D448 (GRandInRange), func_0011B340 (MATRIX3 inverse, VU), NormalizeRotateMatrix3,
func_0011B570 (rotation matrix from axis-angle VECTOR), func_0011B628 (euler -> MATRIX3), func_0011B720, func_0011E208
(pan/tilt/r -> VECTOR), func_0011E958 / func_0011EF08 (VECTOR -> pan/tilt(/r/z)), DecomposeRotateMatrixPanTilt,
func_0011E9F8 (clamp VECTOR length), func_00117030 (cubic Hermite, the "two nops at function start").

**Key discovery: `nop; nop` right before a div.s / sqrt.s** (function start, branch targets: 0x117030, 0x11E9F8,
0x11CAB0, 0x11D508, PosSmooth 0x11F13C, 0x11EA60, DecomposeRotateMatrixRad 0x11BDD4/0x11BDF8, 0x117120) is NOT produced
by our assembler. Reproduce with source asm: `__asm__ __volatile__("nop\n\tnop")` placed just before the C division
(best - gcc still allocates the div normally, 0x117030), or `asm volatile("nop\n\tnop\n\tdiv.s %0,%1,%2")` /
`"nop\n\tnop\n\tsqrt.s"` (0x11E9F8). A single `nop` before div.s after an lwc1 (PosSmooth) needs a 1-nop variant.

Techniques:
- **Factory with two vtables** (`p->vt@0xC`, `p->vt2@0x1B0`, `p->0 = p->4 = 0`): multiple inheritance, second base
  has data then virtuals: `class M { M(){} char pad[OFF-0x10]; virtual void G(); }; class X : public BASIC, public M
  { char pad2[CB-OFF-4]; virtual void F(); }; return new X;` (BASIC as in func_00111588.cpp). Gives the $v1 form.
- VU matrix code: whole-block asm with `register qword vN __asm__("vfN")` inputs/outputs + struct return (B340);
  per-row "j" asms for MATRIX3*MATRIX3 with the *A rows listed first* as operands (B720: operand order decides which
  dead input register gets reused for the output).
- Length helper: `vmul/vaddw/vadday/vmaddz` asm with the "one" temp as a **fixed `$vf4` clobber** fixed regalloc in
  NormalizeRotateMatrix3 (in other functions the plain "=j"(one) output was right - try both).
- Declaring a callee `void` instead of returning a pointer changed `$v0`/`$v1` for a later address (B720).
- Float temps for common subexpressions (`sxsy = sx*sy`) fixed FP reg order (B628).
- VECTOR -> components: GetX/GetY/GetZ (mtc1/prot3w/pextuw) asm accessors from notes/1A0000; storing a VU length as
  int: `asm("qmfc2.ni %0,%1" : "=r"(int) : "j"(l)); *(int *)pf = n;` gives qmfc2+sw (float gives mtc1/swc1).
- sqrt.s: `asm volatile("sqrt.s %0,%1" : "=&f"(r) : "f"(x))` (PanTilt, E958). Where the target has `nop; nop`
  right before the sqrt.s (0x11D508, 0x11CAB0), `"nop\n\tnop\n\tsqrt.s"` in the asm reproduces them.
- Returning a qword float result through a union (`mfc1; sq; por`): `asm("mfc1 %0,%1" : "=r"(u.q) : "f"(g))` (F198 wip).
- Constant 1/92698 = 0x3734FC67 (GRandInRange scale); 1e-4 = 0x38D1B717 is the usual epsilon.

## Round 7
Matched (5): GTrunc__Fd, func_0011C318 (MATRIX4 affine inverse, VU block asm), func_0011CAB0 (max row length, sqrt),
func_0011D508 (CSolveQuadratic), GSmoothA__FffffP4SMPAPf.
- GTrunc: the "dli" toolchain issue is gone; the remaining diff was fixed by operating on the parameter in place
  through a pointer: `DBL *p = (DBL *)&g;` (bitfield union {frac:52, exp:11, sign:1}), `g += 1.0` for the round-up
  path, `return g`. Using a separate local union copy makes gcc write the bitfield insert back into the copy's reg.
- func_0011C318: same recipe as func_0011B340: `register qword vN __asm__("vfN")` inputs declared in the order
  [r1 vf2, r2 vf1, r0 vf3, r3 vf4] (load order = last declared first, then the rest in order), r3 as "+j"
  (it's negated in place), vf9/vf10 clobbers, outputs vf5..vf8.
- func_0011CAB0 / func_0011D508: with the round-6 auto nops, plain sqrt asm `"sqrt.s %0,%1" : "=&f"` (non-volatile)
  works; the max-of-3 was `if (d1 < d0 && d2 < d0) g = d0; else if (d2 < d1) g = d1; else g = d2;`.
  CSolveQuadratic Sly 2 = `(float a, float b, float c, float *ax)`: `c *= 4; alpha = b*b - a*c; if (alpha < 0)
  return 0; a = a + a; alpha = sqrt(alpha)/a; beta = b/a; if (fabsf(alpha) < 1e-4f) {*ax = -beta; return 1;}`
  then ax[0] = -beta+alpha, ax[1] = -beta-alpha, swap if ax[1] < ax[0]; return 2. Builtin sqrtf gave a different
  div order; the asm sqrt matched.
- GSmoothA: `SMPA : SMP { float gAccel @0xC }`; the term is `0.5f * psmpa->gAccel * dt * dt` (fast-math reassociates
  it into the target's (dt*0.5)*a*dt order; other spellings don't).
- Clamp idiom `if (g < lo) return lo; if (g > hi) return hi; return g;` as an inline GClamp(g, lo, hi) gives the
  target's `bc1f; b; mov.s` + `bc1tl` shape (func_0011EE08, func_0011D608), plain if/else-if does not.
