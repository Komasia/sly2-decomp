## Techniques
- **KEY: "factory" vtable-in-$v1 pattern SOLVED** (`p = alloc(); memset(p,..); p->vt = X; ctor(&p->m); p->vt = Y`):
  declare the callees with their real pointer return types - memset `void *func_002333B4(void*,int,int)` and
  member ctors returning `this` (`void *func_00167310(void*)`). With `void` returns gcc picks $v0 for the vtable
  constant; with pointer returns it picks $v1 like the target (func_001CDCD0). Same cause for func_001AE478
  (ctx ctor `int func_001AE478(H*)`) in func_001C76D0 - probably also fixes func_0013BE58 (notes/130000.md).
- Argument evaluation order (right-to-left) shows in the scheduling of arg-register setup: a float param's
  position in the prototype matters, e.g. func_001C14A8(a, i, float g, p, f) (func_001C15F8).
- Brute-force statement permutations (store order) with a small script: found the order for func_001C90D0
  (ThreadParam fill) and func_001CBEE0.
- **Tagged-pointer flags at LO+0x40** (`xori 1; andi 1; beqz`): `v = p->x40; if (FPtr(v)) *(int*)v |= 2; else p->x40 = v|2;`
  with `static inline int FPtr(int v) { return !(v & 1); }` - writing `!(v&1)` / `(v^1)&1` directly in the if
  gives different branch layout or scheduling; the inline bool function matches (func_001C8280, 1C4E50, 1CDDC8, 1CD9E0).
- Constant assigned *before* an intervening call keeps a variable in an $s reg (target `addiu s0,2` between calls):
  move `n = 2;` above the last call in the block (func_001C6B28).
- A global's address + member offset left unfolded (`lui/addiu D; addiu +8` in delay slot) = the address went through
  an inline function parameter: `static inline short Find(struct X *px, ..) { return f(px->t, ..); }` (func_001C7B18).
- Callee return type (void vs int) changes which temp reg ($v0/$v1) later constants use (func_001C76D0, func_001AE478).
- VU0 distance: one asm per VU instruction ("j" constraints) gives the target's vf1/vf2 allocation; a single
  multi-instruction asm swapped vf1/vf2 (func_001C0880). qmfc2 into an `int` "=r" to get a plain `sw` store.
- **`if (A || B) return 0; return 1;`** gives the branchy `bnez v0; li v0,0 / li v0,1` result (not sltiu/xori);
  `if (A) return 1; return f() ? 1 : 0;` does not (func_001C5570, func_001C3E90).
- **Struct passed by value in C++** (`int f(S*, qword, M m)` with a 0x30-byte M): g++ copies to the stack at the call
  site (lq/sq pairs, pointer in a2); C passes the original address. Write the file as .cpp with extern "C" decls
  (func_001CF518).
- VU0 length-squared compare (func_001CEFC8/F010/F058): one volatile asm per VU instruction, the float limit
  assigned *after* the qmtc2 asm and passed as a dummy "f" input to the next asm, qmfc2 into a float with "=r".
- Store order: chained float zero assignment `a = b = c = ... = 0.0f` stores right-to-left; combine with the
  last-store rotation (func_001C42E8).
- Address `&a[c - 1]` with base+off order: `&p->a[p->c] - 1` (func_001C2170).
- Element pointer `struct E *pe = &p->a[p->c++]; pe->q = q;` for append-to-fixed-array (func_001C2148).
- Unused `int unused[4];` gave the extra 0x10 of frame (func_001CA308).

## Session 2 findings
- **sqrt.s with dest != src** (func_001C4330): `static inline float sqrtf_(float x) { float r; asm volatile("sqrt.s %0, %1" : "=&f"(r) : "f"(x)); return r; }`
  (earlyclobber gives the target's f2<-f1; builtin sqrtf lets the scheduler hoist float constants above it).
  `a < b ? b : a` gives `max.s d, a, b` operand order of the target (GMax).
- Loop that exits via `return pv` where pv==0 got jump-threaded to an earlier `return 0`; use `goto out; ... out: return pv;` (func_001C0A40).
- Fixed-count init loops over a global struct array: `for (i...) { pb = &D[i]; pb->p = BASE + i * STRIDE; ... }` gives the
  target's pointer/counter loop shapes (func_001C2A78); explicit running pointers do not.
- Loop bound re-read from memory (`for (j = 0; j < p->xF8; j++)` after `p->xF8++`) gives the hoisted copy (`daddu a1, v1`) (func_001C1BA0).
- Switch bodies are laid out in source order; check which case goes where before reordering (func_001C4468, func_001C8350).
- **Struct return + by-value struct arg** (func_001CD308): target `MAT tmp(sp+0x40) = f(); copy -> sp+0; g(sp)` came from a local
  declared at the top (`MAT mat; int unused[4];`, first used as an out-buffer) and later `mat = f(...); g(mat);` (C++).
- CRef by-value pattern (func_001C7C30/func_001C8188, see wip): `{ CRef r(f != 0); SetPv(pv, r); }` with inline
  `SetPv(void *pv, CRef r) { func_00258200(pv, r, D_003D4A60); }` and `CRef func_00258200(void*, const CRef&, void*)` gives the right
  stack slots (r 0x10, copy 0x20, ret 0x30) and 3 dtors; remaining diff: target loads `lui s0, %hi(D_003D4A60)` before the copy-ctor call.
