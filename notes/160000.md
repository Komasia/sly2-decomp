# Notes for 0x160000-0x170000

## Module map
- 0x160000-0x161400: frame/packet management (OpenFrame, FinalizeFrameVifs/Gifs, frame struct at D_002DEA4C).
- 0x161400-0x165FFF: a "job/task" style system: objects with list arrays at +0x8C.., a global manager D_002DEB30,
  messages via vtable slot 3 (Msg). Lots of functions take/return the same object kinds.
- 0x166900-0x166E90: GIFS methods (0x166920 = GIFS ctor, 0x166968 = AddPrimEnd, 0x166BD8 AddPrimPack,
  0x166E90 = PackAD, 0x1669E0 = EndPrim).
- 0x16F148-0x16FFxx: gs.cpp (SyncVBlank, ResetGs (intc handler), SwapGsBuffers, RestoreGsBuffers,
  SendDmaSyncGsFinish, BuildClearGifs).

## Classes
- Message interface: classes with vptr at +0xC (base class has 3 ints then virtuals). Slot 3 (0x18/0x1C) =
  `Msg(int msgid, int, int cArg, void **apvArgs, int)`. Arguments are passed as an **array of pointers**:
  `void *apv[2]; apv[0] = &n; apv[1] = &m; p->Msg(0x11, 0, 2, apv, 0);` — writing it with a single `int *pn`
  and `&pn` does NOT match (vt load scheduling differs). Declare as real C++ class with virtuals:
  `class OBase { int a,b,c; virtual V1(); virtual V2(); virtual Msg(...); }; class O : public OBase {...}`
  (if data members are in the same class as the virtuals, g++ puts the vptr after them!).
- Task object (0x161400-0x165000 functions): +0x50 int disabled, +0x54 int state (-1 none, 0..3),
  +0x58 float tStart, +0x5C/+0x60, +0x64/+0x68 sub-objects (state at +0x54), +0x78 float dt,
  +0x7C int counter / owner ptr, +0x80 first child (+0x84 = next sibling, +0x64 field), +0x80 also obj w/ vtable,
  arrays: {int c; E *a} at 0x8C (16-byte E), 0x94 (24-byte E), 0xA8 (16), 0xB0 (24), +0xC0, +0xCC LO*,
  +0xD8 CRef-ish, +0xF0/+0xF4/+0xF8 ints (saved/restored by CSave guard).
- CSave guard (0x164AA8.., 0x163C28): stack object {X *p0; X *p4; int n8; int nC} with inline ctor/dtor;
  matches as a real C++ class with an inline destructor (-fno-exceptions). Ctor variant (X*, int, int) — passing the
  values (not the source pointer) is what lets gcc hoist the loads.
- VIFS/GIFS usage: func_0016E228/0016E1A8 use UnpackHelper(UPK_V4_16, 11, 10, 0, &pun) + memset(pun,0,0x58);
  AddVifMscal(symbol). GIFS on the stack: ctor func_00166920, no dtor.
- func_00160918(DMAS*, void *pvStart, void *pvEnd) = AddDmaRefs((end-start+15)>>4, start).

## Techniques
- memset (func_002333B4) declared returning `void *` changed register allocation (v1 vs v0) in func_001613F8.
- `ExitHandler()` = `asm volatile("sync\n\tei")` (ResetGs, func_00167F78).
- Interrupt handler register read: non-volatile `*(uint*)0x12001000` gives the folded `lw 0x1000(lui)`.
- Bitfield GS CSR struct (FIELD bit 13) gives the srl/andi form.
- `f = (p->n == 1); if (g) f = 0; if (f)` reproduces `xori/sltiu/movn`.
- Store-order rotation again: for 3 stores of -1 and an arg store, source order == ascending offset matched.
- Early-return `if (*pc < cMax) { pe = &ae[(*pc)++]; ...; return 1; } return 0;` (func_00161F10).

## More techniques (second half)
- C++ guard objects with ctor/dtor (`FRAME` = func_001AE478 ctor / func_001AE4A0 dtor(this,2)): declare
  `class FRAME { int a[4]; FRAME(); ~FRAME(); };` in a .cpp file and just declare a local - the C++ ctor's
  `this` return value changes register allocation vs a plain C call (fixed the v0/v1 issue noted for 0x13BE58,
  e.g. func_00165C98, func_00161660, func_001624A8, func_001635F8).
- ALLOCREQ fill through an inline `PvAllocReq(ALLOCREQ *preq, int cb, int nKind)` gives the
  `addiu s0,sp,0x10; sw cb,0x10(sp); sw nKind,4(s0)` pattern.
- CSave guard has several ctors: (X*, int nF4, int nF8) for the object itself, and an "owner" variant
  (X*, int nF0, int nF4, int) storing into m_p0 (fields F0/F4). Same dtor. Used all over 0x163000-0x165600.
- A pointer computed inside a loop as `E *pe = &ae[i];` becomes a giv initialised in the preheader (after the
  entry test) - this is what the target does; `pe = ae; pe++` puts the init before the test (func_001620B0).
- `iqw = n * 3 + 1` written as an expression (giv) instead of a separately incremented variable (func_00167FC0).
- Two loops sharing `i`/`px` variables declared at function scope reproduce shared s-regs (func_00167FC0);
  conversely a second loop needing a different register needs its own `int j` (func_001635F8, func_00163170).
- `static inline int FField() { return ((CSR *)0x12001000)->FIELD; }` then `x = FField() == 0` gives
  srl/andi/sltiu (direct expression gives xori) - RestoreGsBuffers/SwapGsBuffers.
- `static inline int Max(int a,int b){return a > b ? a : b;}` + `return n < 2 ? n : Max(x, 1);` kept the
  constant in a register (func_00163430). `int nMax = 99; ... Min(pct, nMax)` hoisted 99 (func_00161660).
- A by-value struct param with a declared copy-ctor (`RGBA(const RGBA&)`) is passed by invisible reference
  (BuildClearGifs__FP2QWG4RGBAi). Local `int ai[] = {..}` initialisers come from .rodata via ldl/sdl.
- Jump-table switch: include explicit empty cases (`case 3: break;`) so gcc builds the same dense table.
- Switch case bodies are laid out in source order; reorder the cases to match the target body order.
- WaitSema/SignalSema (func_00234A60/func_00234A40) return int; declaring them int changed v0/v1 choice.
- `unsigned long` 64-bit GIFS PackAD constants: write the literal 64-bit value; the build reproduces the
  original `ori/dsll` expansion.
- GS register bitfield structs that are copied with ldl/sdl need `__attribute__((packed))` (see wip
  BlendDisplayOnBufferMismatch).

### Techniques that fixed old near-misses
- `for (i = 0; f && i < p->c; i++) { px = p->apx[i]; ... }` (indexed, flag in the test) put `i=0` in the blez delay slot (001645D0).
- Extra register copy of a field for a switch: read the field again in the switch (`switch (p->n)` after `nState = p->n; nNew = nState;`) -
  gcc CSEs the load but keeps the separate copy (00165B40).
- `ac ? ac + i + 1 : 0` (pointer + int, not `&ac[i+1]`) gives the "walk from ac, +0x18 before use" giv; with pa/pb locals
  declared before it the preheader order matched (001699E8).

  reorg's beql choice (00169EB8).
- `for (int j = 0; j < 3; j++)` instead of `for (j = 2; j >= 0; j--)` fixed s-reg copy order (00160E68).
- `if (p->f7c && p->f7c->f68 == p) n++;` (instead of save/restore of n) keeps the param in its arg reg (00164100).
