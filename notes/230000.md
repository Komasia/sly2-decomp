## Toolchain finding

* **`sq` regions (game + 989snd + newlib libc)**: `ee-gcc2.95.3-136` with `-O2 -G0` (plain C) matches
  exactly. For float / VU code add the game flags: `// SLY2_CFLAGS: -O2 -G0 -ffast-math -mvu0-use-vf0-vf31`.
  94 functions matched this way in this session (all of them func_ names in 0x230000–0x2331FF and
  0x2550A0–0x259DF0, plus a few library leaf functions).
* **`sd` region 0x234F48–0x2550A0 (Sony SDK libs, libgcc, libm)**: compiled by a compiler we do NOT have.
  None of the five bundled ee-gcc builds (2.95.2-273a, 2.95.2-274, 2.95.3-107/114/136), with any of
  -O1/-O2/-O3, -G0/-G8, -fno-delayed-branch, -mips3, -mgp32, -mlong32, -msoft-float…, reproduce its
  characteristic features. All five 2.95 builds produce byte-identical output for every test below. The
  features are:
  1. callee-saved GPRs spilled with **`sd`** at the bottom of the frame and `$ra` above them
     (`sd s0,0(sp); sd ra,0x10(sp)`); every 2.95 build emits `sq s0,0x10(sp); sd ra,0(sp)`
     (__throw_type_match, IsT10K, _sceMpegError1, func_00240AA0).
  2. **sibling-call optimisation**: `j func` tail calls with the epilogue in front (52 functions, e.g.
     func_00239AB0 `SetT2(0xB0001000, x)`, sceSifSendCmd-type wrappers, serialPutchar, _waitIpuIdle).
     gcc 2.95 never emits sibcalls.
  3. **`mult1`** (EE pipeline-1 multiply) used by the scheduler (scePadGetState); 2.95 never emits it.
  4. the delay slot of a loop's backward branch is **never filled** (memclr, kCopy*, kputchar), and short
     loops are padded GNU-as style (one more nop than tools/asfix.py adds: kputchar has 3).
  5. 64-bit by-value struct fields are spilled with `sd`, not `sq` (__make_dp).
  6. hard-float varargs frame without float-register saves (sceSnprintf: frame 0x90, `va` = sp+0x68).

  This combination points to Sony's **ee-gcc 2.96** (SDK 2.x/3.x library compiler), which is not in
  tools/compilers/bundle. Until such a compiler exists, only leaf functions with no loops, no tail calls
  and no saved registers can match in this range (the 47 pre-existing src/lib files plus
  __register_frame_info_table and sceMpegAddCallback are of that kind; those also compile with
  2.95.3-136 `-O2 -G0`). Note that register choice can still differ (_decodeOrSkip gets $a3 in the target,
  $a1 with 2.95).

## Tips / patterns found

* 989snd wrappers: `void f(int a, …) { int buf[N]; buf[0]=a; …; func_002325E0(CMD, 4*N, buf); }` or
  `func_00232838(CMD, 4*N, buf, x, y)` match directly. If a 9th argument is read with `ld` from the
  stack, declare it `long` (func_002330D0).
* Game ref-counted pointer (0x256C58/0x256D40/0x257250/0x257450): `{int ref; …}`; the release path
  calls the recursive dtor `(…, 2)`, then CRef dtor func_00129EC8 with **one** argument, then a pool free
  `func_0011CD98(&pool, p)`; `if (flags & 1) func_001AE520(this)`.
* Interface ptr assign (0x258040/0x259B48/0x259BB0): vptr at +0xC, AddRef = slot 1, Release = slot 2.
* func_00258658/func_002590F0 family: copy-on-write of an object at +0xE4 using a `{0x100, 0x10}` alloc
  descriptor on the stack (func_001AE238 = clone, func_001AE1D0 = alloc, func_001AE2A0 = alloc).
* Small "is n in set" helpers (func_00230310/230348/230380) are plain `switch` with
  `case …: return 1;` and `return 0;` after it. Do not list the 0-cases, or extra blocks appear.
  Jump tables are at 0x2A9EC0/0x2A9F20/0x2AA000 (read them from the ELF, file offset 0x80 + addr - 0x100000).
* `== 0xFFFFFFFF` on an `unsigned int` produces `lui 0xFFFF; ori 0xFFFF`, where `-1` gives `addiu -1`
  (func_00231E90).
* Switch case order matters for block layout (func_00258B70: cases 2,3,8; func_00258D98: case 2 before 1).
* `if (*r != k) return D; return r + 0x30;` vs the reverse flips beq/bne (0x258C60 family).
* `m[0] = m[5] = m[10] = m[15] = 1.0f;` (chained) reproduced the store order and register allocation in
  func_00231100. Separate statements did not.
