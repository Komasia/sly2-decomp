- Owner flag bit 60 of ulong at +0x28 (`(int)(fl >> 60) & 1`).

## Techniques that mattered here
- `return x ? 1 : -1;` vs `if (x) return 1; return -1;` -> movn vs branch forms; try all.
- `int f = 0; if (a < 2) { if (a >= 0) f = ...; }` keeps two branches (no sltiu fold).
- Unused `int unused[4];` reproduces a 0x10 empty frame (func_001711F0).
- Two separate qword stores whose loads are interleaved with an unrelated float store: use a 32-byte struct copy
  (func_0017DD38).
- Chained assignment order can reproduce odd store orders (func_00173158: `a = c = b = 1`, InitZpr: `zpk = zpk2 = x`).
- `float t = g_clock.t; p->x = t + f();` forces the clock load before the call (func_00179E80).
- Early-return chains `if (a) return 0; if (b) return 0; return f();` produce the duplicated `ld ra` epilogue form;
  `int f; if (..) f = 0; else if (..) f = 0; else f = call(); return f;` produces the shared one.
- A nested if-chain on an int range: emit order follows source; the returned-last value goes in the fallthrough.

- Virtual-call temporaries must be block-scoped per call site (`{ struct O *o = ...; struct VTE *e = &o->vt[8]; ... }`);
  sharing one `o`/`e` across switch cases changes register allocation (func_0017CD00/0017D058).
- Struct-returning call into a local that is then passed by pointer (func_0017FB50): only matched as C++ with
  `MATRIX3 m; m = f(...);` (temp at sp+0x30 then copied to m at sp); C always elides the temp.
- Range test `2 <= s < 4` kept as two slti branches with `if (s < 4) { if (s >= 2 && ...) }` (func_0017A7F8).
- Message handlers `int OnMsg(S *p, int msg, M *pm)`: `if (msg == 9 && ... ) switch (pm->n8) { case X: ...; return 1; }
  return BaseOnMsg(p, msg, pm);` (func_0017B690, func_001750E0).
- Big-struct init: `struct F f; memset(&f, 0, sizeof f); f.x = ...; Send(&f);` with F = 0x60/0x70 bytes.

### Discoveries
- D_003E1A5C is really D_003DD490.p45CC (0x3DD490 + 0x45CC). Declare `struct G { char pad[0x45CC]; struct W *p45CC; }`
  and write `D_003DD490.p45CC->n28`: gives the `lui a0,0x3E; lw v0,0x1A5C(a0)` form scheduled after stores
  (fixed the old func_0017D360 near-miss and func_0017DA28).
- Vector component helpers (GetX = mtc1, GetY = prot3w, GetZ = pextuw with "=r"(float)) from notes/1x0000 solve the
  "VECTOR in GPR" pattern: func_00173588 (old skip) and atan2(d.y, d.x) of a vsub result (func_00172320/172018).
- `-v` via `U u; qmtc2 -1.0f -> u.q; vmulx` (union forces the sqc2 to stack) matched func_0017CB80.
- XY distance: separate asm stmts {vsub}, {vmul.xy+vaddy.x}, {vsqrt;vwaitq;vaddq.x}, {qmfc2 "=r"(float)} (func_00172658 style).
- `p = &x.v` passed to a virtual `int f(this, struct B*)` where only B.v (offset 0x30) is used later: struct B {pad[0x30]; qword v;}
  explains `a1 = sp` + `lq a3, 0x30(sp)` (func_00175488).
- Struct-return-into-self `m = f(a, b, &m)` needs C++ (.cpp + extern "C") to get the temp+copy (func_0017FD08).
- Big tail-merged state-update switches (func_00172018): write the shared `p->n48 = 0;` once after the inner if/else so
  gcc's cross-jumping merges `Set(p,2)`/`Set(p,1)` blocks between cases.
- Combine early-exit tests into one `if (a || b || c) return 0;` when all fail branches jump straight to the epilogue
  with v0=0 in the delay slot (func_00175D00).
- A switch whose layout order differs from case-value order: write the cases in layout order (func_00179BA0,
  func_0017C928 case 1,2,0).
- `!(x < c)` gets turned into `c <= x` (fast-math); to keep `c.lt + bc1f` use goto/if-structure that branches on the
  original compare (func_00173610 wip).
- Jump tables for func_0017D450 (0x2A5610), func_00176458 (0x2A5410), func_00176750 (0x2A5430), func_00172320 (0x2A53A0),
  func_00172018 (0x2A5380).

## Round 7
Matched (4): func_0017E0E0 (.cpp, old wip), func_0017E6B0 (old wip), func_00173610 (old wip), func_0017F930 (new).

### Discoveries
- **Comparison operand order decides which register CSE substitutes after a loop exit.** State loop
  `do { s = p->n1C0; if (s == 2 && f(p)) Set(p, 1); } while (p->n1C0 != s); switch (p->n1C0) {...}`
  makes the switch use the freshly loaded value (v1) like the target; `while (s != p->n1C0)` makes gcc switch on `s`
  and swaps s0/s1 for the whole function (func_0017F930).
- Switch with a jump table where 4 of 5 cases share code: write each case with its own identical body
  (gcc cross-jumps them afterwards); `case 0: case 2: ...` labels on one body made gcc emit compare branches instead
  (func_0017F930, table 0x2A5640).
- VECTOR {0,0,g} passed by value: the notes/1A0000 `Make()` asm (mfc1/pextlw/mfc1/pcpyld in ONE asm) + a dead union
  store `u.q = v;` reproduced `sq s2, 0(sp)` and the 0x70 frame (func_0017F930).
- Old wip func_0017E0E0 (ctor call recomputing &x instead of the hoisted $s4): make it .cpp with
  `struct X { ...; X(); }; inline X::X() { func_002562A8(this); }` and declare `X x;` at the point of the ctor call.
- `(struct SEG *)(p->n34 * 32 + (int)p->p30)` fixed the addu operand/register order (func_0017E6B0).
- Declaring the ctx ctor `int func_001AE478(...)` (not void) fixed the v0/v1 swap in func_00173610 (as in notes/1C0000).
