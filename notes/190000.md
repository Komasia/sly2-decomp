## Techniques that mattered here
- VU0 "j" constraint asms (notes/200000.md) work well. Locals that the target keeps in *memory* (sqc2/sq to the
  stack, reloaded later) are **unions** `union { qword q; float f; }` - gcc puts unions in memory, plain qword
  locals stay in registers (func_001991A0, func_0019EA00).
- Matrix*vector asm: operand order of the "j" inputs decides VF register allocation. For
  `vmulax ACC,r0,vx / vmadday ACC,r1,vy / vmaddz out,r2,vz` the vector must be the *first* input operand
  (func_001991A0).
- Float loaded into a GPR via `lw` for qmtc2: pass an int-typed value as "r" input. To get it into an $s register
  the target reused, assign it to the dead pointer param (`p = (P *)p->g14;`) (func_0019EA00).
- Unused local VECTOR initialised from a .rodata zero vector still emits lq/sq when it's a struct (vec.h VECTOR),
  not a qword (func_0019FC30).
- Virtual call argument scheduling: the *prototype order* of float vs int args matters even though they go to
  different register files: `(this, float, float, VECTOR*, int)` matched where `(this, VECTOR*, float, float, int)`
  did not (func_0019DE58). Permute parameter positions when only arg-setup order differs.
- **Spilled qword pseudos**: a qword local that lives across a call is spilled by reload to a stack slot *after*
  the declared locals, and its reload for an asm "j" operand is emitted last but gets the first VF register.
  This explained "lqc2 vector last but in vf5" in func_0019F3F8 (use a plain qword local, not a union).
- Struct-returning call assigned to an existing local (`m4 = f(...)`) uses a separate temp + copy only in C++
  (.cpp); in C gcc passes &m4 directly (func_0019DF70 wip).
- **Cross-jumping**: when the target has one call site reached by `b` from several cases (and the default block
  placed after it), write the identical call at the end of every case; gcc merges them (func_001942F0).
- Dot product / length asm: `vmul.xyz %0,a,b; vaddw.x %1,$vf0,$vf0w; vadday.x $ACC,%0,%0y; vmaddz.x %0,%1,%0z`
  with "=j"(r), "=&j"(t); tie r to the input that dies ("0") to reproduce the target's register reuse.
  Separate `vsub` asm + "+j" length asm matched func_0019FEB0's distance code. Extract the float with
  `asm("qmfc2.ni %0, %1" : "=r"(g) : "j"(r))` (gcc adds the mtc1).
- Loop over array with `e = &p->ae[i]` inside the body (not a pointer increment) gave the target's giv placement
  (func_0019FAF8).
- Chained zero stores: target order 20,1c,18,14,10,2c,28,24 came from `x10=x14=x18=x1c=0; x24=x28=x2c=0; x20=0;`
  (func_0019D330).
- Comparing switch with `beql v0,s1` where s1 holds the switch value: write a nested `switch (p->x20) {case 0: case 1:}`.
- g_clock.t via `struct CLOCK { float t; float dt; } D_002DDED0; D_002DDED0.t` changed store scheduling vs
  `extern float D_002DDED0` (func_001928F8, also noted in 1A0000.md).
