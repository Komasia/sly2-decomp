## Agent lane1

# lane1 notes (agent 1)

## General lessons
- **sched1 "birthing insn" boost (gcc 2.95 haifa-sched adjust_priority/birthing_insn_p).** When an insn becomes ready in the
  pre-reload scheduler and it SETs a register that is live and has REG_N_SETS == 1 *in the whole function* (e.g. $6/$7 when the
  function has only one 3/4-argument call, or a pseudo set once), its priority is raised to max_priority, so it jumps the queue.
  So the order of the arg-setup insns of a call (a0..a3, lui/addiu) depends on how many OTHER places in the function set the same
  argument registers. Adding a dummy call with more args elsewhere in a test copy flips the order; that is how you test it.
  Next tie-breakers (rank_for_schedule): priority, INSN_REG_WEIGHT (smaller wins; `move $a1,pseudo` that kills the pseudo = 0, other
  sets = 1), class vs last scheduled insn, number of dependents (more wins), lowest LUID. sched2 then keeps sched1's order as LUID
  for its ties, and dbr puts the LAST insn of the block into the call's delay slot.
- Use `-da -fsched-verbose-5` and read the "scheduling visualization" table of `.sched` (sched1) and `.sched2` for the block.
- A pseudo set before a call is hoisted by sched1 above the call only if it is not dependent on it; insns after the call in the stream
  get REG_DEP_ANTI on the call.

## func_001ACFE0 - MATCHED (src/hand/func_001ACFE0.cpp)
The CRef-call tail (case 34) is exactly the func_0013D328/func_001D54B8 idiom:
`static inline void SetPv(O*po,const CRef&r,void*){CRef arg(r); const CRef &ret=func_00258200(po,arg,D_003D4A60);}` and the call site
`O*po=D_003E0FE4; CRef ref(true); SetPv(po,ref,D_003D4A60);` The call-site context argument is evaluated before the copy ctor call
(and then CSE'd away), the body's own D_003D4A60 lands after it. Every earlier variant ("Send" with a by-value CRef parameter, direct
member call, free function) had the right instructions but a2/a3 setup in the wrong order (2/97) because with a single 3-arg call in the
function the scheduler boosted the a2 and a3-low setters. Using the body's D_003D4A60 (not the unused parameter) is required.

## func_001C9190 - near-miss, 6/147 raw diffs, aligned 5 (build/hand_wip/func_001C9190.lane1.v4.cpp, no pins/asm)
Plain C++ rewrite (no asm, no pins). What got it from 41 aligned to 5:
1. Inner loop written `for(;;){ BeginFrame...; if(status.count!=0)break; body }` (same code as the comma-`while`, but matches the
   147-word length).
2. `do{ D_002DEA4C->flags&=-2; }while(0);` - a do/while(0) adds a loop-depth level, REG_N_REFS weights uses by loop depth, so
   hi(D_002DEA4C) becomes the highest-priority global after the matrix/builder pointers and gets s3 (target order s0 matrix, s1
   builder, s2 hi(BE538), s3 hi(DEA4C), s4 &C10C0, s5 &clock, s6 hi(3A40), s7 hi(BBB60), fp hi(C10C0)). This is global-alloc priority
   = floor_log2(n)*n/live_length with n weighted by loop depth (use in depth-2 loop counts 3, depth-1 counts 2, set counts 1);
   compare numbers in the `.greg` dump ("N regs to allocate: ..." is the priority order).
3. `float t = -*D_002DD314 + clock->frameT;` (not `frameT - *p`): adds one neg insn, which changes the loop size and the
   sched1 order of the first load group; the whole first block then matches.
Remaining 2 groups: (a) `addiu a1,zero,1` (m_fCheckCnt) is rematerialised late into v0 instead of early into a1; (b) the lui for
D_002DEDBC is v0 not v1. Cause (verified in the loop dump): loop.c moves single-use `lui`/const insns out of the inner loop in its
second pass only while `threshold*savings*lifetime >= insn_count` (threshold ~95 here, decreasing by 3 per move; insn_count is the
inner loop size at that moment, 92-94 for my variants). Moved ones become unallocated globals that reload rematerialises into a
round-robin reload register. The target clearly kept const 1 / hi(D_002DD314) / hi(GIFS) local (local-alloc picks a1/a0/v0), i.e. its
inner loop had >= 96 insns at that point (3+ more than mine), probably because gcse PRE did not hoist the single-use `high` insns
(see "PRE/HOIST" lines in the `.gcse` dump). I could not find a natural source change that adds those insns. 144 spelling variants
(search9190.sh style) all stay >= 6.

## func_001BFDB0 - not matched (draft uses 2 pins + asm, rejected by policy); findings

## func_001A3F78 - MATCHED (src/hand/func_001A3F78.cpp, no pins)
Started from build/hand_wip/func_001A3F78.cpp (aligned 17, one $f2 pin). Four independent fixes, in order of effect:
1. `int one = base + 1;` as its own local in the inlined BitIndex (then `result = c ? one : base`) lets loop.c hoist `base+1`
   out of the do-while (`addiu t8,t6,1` before the loop, `daddu v0,t8,zero` inside). With `result = base+1; if(!c) result=base;`
   `result` is set several times so loop.c cannot hoist it. Fixed t8/t9 numbering too. (17 -> 16 but straightened the loop head)
2. `pos` passed as `const qword &` to Length/Score (aggregate address taken) gives it a stack home at 0x40(sp); the per-iteration
   `lqc2` becomes an invariant memory load and loop.c hoists it in front of the inner loop (`lqc2 vf3,0x40(sp)` at the top of
   the `if (word)` block) - this fixed ~60 instructions of schedule (16 -> 6). A pseudo that is merely spilled gets reloaded
   inside the loop and is never hoisted.
3. Reload picks the scratch GPR for an asm `"=r"` float output (qmfc2 temp) and for the block-move scratch (ldl/sdl) with
   `order_regs_for_reload` (non-live call-used regs in numeric order, round-robin over spill_regs). Our 'v0, a1' vs target 'a1, a2'
   was a one-reload shift: writing the *phase-1* qmfc2->mtc1 also as `asm("mtc1 %1,%0" : "=f"(f) : "r"(qword))` (gcc itself emits the
   qmfc2 as an input reload of the "r" qword) makes phase 1 take the first GPR spill reg (v0) and phase 2 then gets a1, a2. 6 -> 0 (with pin).
   The same form also fixed the qmfc2/mtc1/sqc2 order in phase 1 (asm-fed qmfc2 has a latency stall that let the sqc2 slip in).
4. The `register float f asm("$f2")` pin was replaced by one function-scope `float score;` shared by the plane-distance test and
   the ranking loop (it is live across Length's f0/f1 temporaries, so allocation lands on f2). Pin count 0.

General lessons: (a) "qword param that is read inside an inner loop": make the callee take `const qword &` so the load is a hoistable
memory invariant; (b) when scratch registers of reloads are off by one slot, convert an earlier `qmfc2`-in-asm to gcc-emitted
qmfc2 (`mtc1` asm with `"r"(qword)`); (c) sharing a float local between sections reproduces odd FP register picks without pins.

## func_001DDB08 - near miss (best build/hand_wip/func_001DDB08.c, aligned 2, one pin) - still open after ~40 checks
Remaining diff (pinned draft): target schedules `addiu a0,sp,16 ; lw s1 ; daddu a1,sp ; sd ra ; lui s0 ; sw v0 ; addiu s0,s0,lo` (the `lui s0` is

- Natural (no pin) forms always give pv=s0 (local-alloc picks the first callee-saved for the single-block pseudo pv) and the pg address as
  `lui v0 ; addiu s1,v0` (hi/lo only share a register when the address pseudo is block-local, as in the reduced test, or hard-reg pinned).
- The Ghidra/asm structure is CRef ref(0x16,0); copy ctor 1291A8; 258200(&ret, D_003E0FAC, &tmp, &D_003D4A60); three dtors; 3 nullable resets; 165E38(&D_003D4A60).

## func_001E9858 - MATCHED (src/hand/func_001E9858.cpp, no pins; asm = VU0 macro + MMI only)
Started from build/hand_wip/func_001E9858.codex18v2.cpp (aligned 10 but 7 pins + instruction asm). What each fix was:
1. The codex "WORK" struct fields `axis`, `nextEntry`, `world` are NOT locals-in-a-struct. In the target they are spilled pseudos:
   stack slots 0x8C0/0x8D0/0x8E0 sit *after* the real locals (distance at 0x8B0) in allocation order axis, next, world. Use plain locals
   (`qword axis = func_001A6318(p)->c.q; int next = j+1; qword world = Point(...)`), keep WORK = {phase, direction, basis, temporary, inverse, distance}.
   Spilling gives `lq v0,0x20(v0) ; sq v0,0x8C0(sp)` (reload scratch = first free reg v0) - no barrier/ordering asm needed any more.
2. TransposeInto: a single asm with 7 pinned outputs -> two asm statements (pextlw/pextuw with 4 early-clobber temps, then pcpyld/pcpyud with
   3 early-clobber outputs). Temps now allocate before the inputs (v0,v1,a0,a1 vs inputs a2,a3,t0) as in the target, outputs t1,t2,t3.
3. `&phase->hit` read through the struct (`w.phase.hit`) instead of the pointer: fewer refs of the `&w.phase` pseudo, which then lands in s7
   by itself (global-alloc priority = floor_log2(refs)*refs/live_length; s-regs are handed out in that order).
4. node vs k s4/s5 tie was priority 0.720 vs 0.726; the changes above shifted lengths by one and the order flipped to the target's.
General: for global-alloc ties, compute the priorities from the *.lreg dump ("used N times across M insns") - a script is easy
(floor_log2(N)*N/M, higher gets the lower-numbered callee-saved reg) and predicts the allocation exactly.

## func_0019AC88 - MATCHED (src/hand/func_0019AC88.c)
No pins. Fix was `float h = t*0.5f; g *= h;` instead of `t *= 0.5f; g *= t;`.
Why: sched1 `rank_for_schedule` breaks ties (priority, reg-weight) by the number of *forward dependences* (INSN_DEPEND count),
then by LUID. Overwriting `t` made the `f13 = t` argument move (insn 71) anti-dependent on the later `t = t*0.5` insn, so it had one
more forward dep than the por a1/a2 moves, ranked above them and was emitted before them (so the por landed in the jal delay slot).
Writing the result to a new local removes that edge, f13 ties with a1/a2, loses on LUID and goes last (= delay slot), like the target.
General trick: when an argument move lands in the wrong place relative to other argument moves, look at the -fsched-verbose-5 dump table
("dep"/forward list); extra forward edges (anti deps from later redefinition of the same variable) raise an insn's rank.
Do not reuse/overwrite a parameter variable after the call if the target doesn't.

## func_001A4AD8 - MATCHED (src/hand/func_001A4AD8.cpp)
Started from v3 (aligned 6). Everything was scheduling-barrier / stream-order, no pins needed. Steps:
1. Copy macro: the old `do{...}while(0)` around everything made the loop-begin NOTE a scheduling barrier right before `d_=D`, so the
   d copy / s_+0x120 / `i+1` / counter init were forced after the m_pb store (aligned 6). `{ }` instead (no barrier) lets them float
   too early (16). The target needs d_/s_ initialised BEFORE the barrier (they are hoisted/free) and `i+1`/counter after it:
   `uint*d_=(D);const uint*s_=(S); do{ int k; for(k=0;k<12;k+=4){...; s_+=4; d_+=4;} }while(0);` (2 diffs).
   NOTE: use an UP-counting k (k=0;k<12;k+=4) with explicit s_+=4/d_+=4: loop.c reverses it itself (counter 8, bgez) and the
   reversed-counter init insn is created after gcse, so it ends up after the PRE-inserted `i+1` in the stream (sched keeps that
   order). An explicit down-counting `j=8; j>=0; j-=4` gave a3=8 before t1=i+1 (wrong order).
2. Second loop's `lui/addiu` hoists: a separate `const uint *src = D_002BFC60.words;` inside the loop body makes loop.c hoist the
   whole address (lui+addiu) and `daddu a3,t4,zero` copy in-loop (target); using the global directly only hoisted the lui.
3. Final 2 diffs were the order of hoisted lui's (D_002DEA28, D_002BFC60, 0x6C03 tag const): loop.c hoists in program order, sched
   ties on LUID. Declaring `VIFS *g = &D_002DEA28; const uint *src = ...;` first in the body and passing the tag inline
   `Write(g, 0x6C03C000|(i*3+0x15))` gives [2E,2C,6C03] like the target.
General: a `do{}while(0)` macro (or any loop) inserts NOTE_INSN_LOOP_BEG, which in sched is a barrier: the first insn after it depends
on everything before and everything after depends on it. Where you put the note relative to the setup insns decides which insns can
float. -fsched-verbose-5 visualization tables (per block) show it clearly.

Fresh rewrite (route builder: nav-graph path between two points). Layout facts, all verified:

## General lessons (reusable)
1. A near-miss draft full of instruction-level asm (lw/lui/swc1/lq ...) is often WORSE than natural C once the asm is replaced by single VU-op asms; strip the asm first
   (001B1328 went 5 -> 3 -> 2 -> 0 and 001CFE88 13 -> 0 that way). GPR<->VU qword copies should be plain C moves (gcc emits qmtc2/qmfc2 itself, and can fill delay slots with them).
2. `"memory"` clobbers on the VU asm statements are a real ordering tool: loads/stores written between two clobbered asms stay between them (explains stores that sit in the middle
   of a vsqrt/vaddq sequence). Copy values into locals first or the barrier forces cse to reload them.
3. Earlyclobber outputs (`"=&j"`) also conflict with registers that died in the IMMEDIATELY preceding insn (local-alloc numbering): a scratch that should share a register with a value
   used just before needs one insn in between (here: keep Sub as its own asm).
4. Local-alloc priority is log2(refs)*refs/life; an allocation-only duplicate operand ("j"(k) twice) moves a value up in vf numbering; a value that is only read once (not "+j") gets
   fewer refs and a higher vf number. Local pseudos are allocated before global ones; a scratch with no later use takes vf1 unless a pin on the long-lived value prevents it.
5. `extern const float` for constants in .rodata changes alias analysis in sched1/sched2 and can fix a prologue order.
6. Partial vector init through a pointer variable (`U *p=&v; p->f[1]=p->f[2]=x; v.f[0]=x;`) reproduces `addiu a3,sp,16; swc1 4(a3); swc1 8(a3); swc1 0(sp)`.
7. Once the asm is clean, a permutation search over statement order (105-720 compiles, in-process via matchtool.compile_src/compare) finds orders no one would guess.
8. Index arithmetic `p + n*12 (+disp)` that ends as separate `mult`/`addu` + a pointer copy needs the table as a real struct array member (`p->tab[n].field`), not casts.
9. gcc fuses `(a*b)+c` into the R5900 `*mul_acc_si_r5900` insn when the product has one use; a target showing separate mult/addu means the product/address came from an array member expansion.

## Facts about local-alloc learned (apply to every register-swap near miss)
1. Allocation order inside a block is by the priority above, NOT by declaration order. Compute it with la.py before trying source variants.
2. A pseudo that is live across a basic-block boundary is NOT allocated by local-alloc (global-alloc does it afterwards, first-fit avoiding conflicts with the
   locals). That is why `lui v1,%hi(X); lw v1,%lo(X)(v1)` exists in the original (hi = local pseudo, loaded value = global pseudo; no conflict at the touching
   point). Seen in matched src/hand/func_001E8008.c (`switch (D_002C3650)`). In func_001BFF28 the same pair appears for the `D_002C0C04` bits load.
3. `ptr = base + off` ties `ptr` with `base` (first dying operand), `x = y + 1` ties x with y if y dies there: the order of the two insns in sched1
   decides whether `sll`/`addiu` share the register of the loaded count (func_001BFF28 loop 2: `int n = v->count; v->count = n + 1; e = v->edges + n;`
   gives the target's order `sll v1,v0,3 / addiu v0,v0,1`; `v->count++` after `e = ...` does not).
4. Splitting one VU distance asm into the 4 asm statements of the matched src/hand/func_001BF980.cpp `Dist2` (vsub / vmul+vaddy / vsqrt+vwaitq+vaddq / qmfc2) lengthens
   the live range of `e` (edge pointer) by two insns, which lowers its quantity priority below the `sll` temp: that fixed the v0/v1 swap in loop 1.
5. dbr (delay-slot filler) never moves the `sw cost` into the branch delay slot of loops 1/2 in the target (it takes the next iteration's first load instead).
   An empty non-volatile `asm("" : "+m"(e->cost))` after the store did that (lane3), but a `volatile int cost` member in EDGE does the same with NO asm and
   no extra refs on `e` (reg_n_refs of e matter for priority). I use the volatile member.
6. Dead `sqc2 vfN,0x10($sp)` of the scalar in the tail comes from passing the `VUF` struct by value to an inline helper; its position depends on source
   order of the arguments/lets.

## CORRECTION to the allocation model (final, validated): la.py default SLACK=2
A quantity reserves its hard register until death+2 (one whole insn after its last use): a quantity BORN in the very next insn after another one's last use
CANNOT share its register (my first inclusive rule, slack 0, was only approximately right). With SLACK=2 `la.py` reproduces every call-free integer/VU block I tested
(a1, b1, c1 dumps: b1 block 5 and 11, a1 block 27 all exact); FP-class blocks and blocks with calls (call-crossing -> s-regs) are not modelled.
Eligibility for local-alloc (checked in local-alloc.c): REG_BASIC_BLOCK>=0 AND REG_N_DEATHS==1 (and class not likely-spilled); everything else (live across a block
boundary, or a user variable with 2+ death points) is a GLOBAL pseudo, allocated after all locals. Allocation-order facts: highest priority first = lowest free hard reg.
Usage: `bash dump.sh build/lane_scratch/w2lane6/X.cpp -da` then `./run.sh la.py X.src.cc` (per-block mismatch list) or `lalloc.py X.src.cc BLK` (quantity table).

## Summary of reusable lessons (wave 2 lane 7)
1. A "goto-loop" has loop depth 0; a real loop doubles every ref count in global/local alloc priorities (floor_log2(refs)*refs/len). When the target's priorities look like a loop but loop.c

## Lessons (for the coordinator / BRIEF2)
1. VU class steering: for `mtc1 %1,%0 : "=f"(f) : "r"(q)` add an unused `"j"(q_vf_pseudo)` input - without it regclass puts the asm result pseudo in a GPR pair (store becomes `sq`, vf numbering shifts).
   87F0: 17 -> 3 aligned; 8B50: three PlaneDistance expansions fixed.
2. gcse PRE reaching registers are numbered in expression-hash-bucket order; reload then hands out spill slots in ascending pseudo number. hash(plus (reg r) (const c)) = (2236 - r_base + r + c) mod S
   (at=reg 1: c+2236; user reg r: r+c+2235), S=(n_insns/2)|1 (see "Expression hash table (S buckets" in the .gcse dump). If two hoisted/spilled temporaries have swapped slots, shifting the regno of one operand
   (unused locals declared earlier) or the insn count flips the order. Matched func_001A87F0 this way.
3. Pseudo number decides cse1's canonical register of an equivalence class (lowest regno), hence whether a loop guard tests the original (`beqz head`) or the loop variable: declare the loop variable at
   function scope (low regno) or inside the loop after the source variable (high regno) to select.
4. A temporary that must be live across a call (`qword pt = m->point;` before a ctor call) is a callee-saved GPR and thereby decides the s-register assignment of the loop pointers.
5. Reading a value BEFORE the branch that conditionally uses it (`qword plane = s->plane; if (...)`) lets reorg fill the delay slot from before (no annulled bnel).
6. Put a float parameter at a different position in a callee prototype (EABI: no change in callee) to change argument-evaluation order and so the order of the arg moves before a call.
