# 0x23C000–0x246000 (libgcc 2.95 + libgraph/dma/cdvd/pad/mc + newlib libm) — gnu-reorder session

## Result
No new exact matches with the available modes. Everything in this range is blocked by at least one of:
* **callee-saved `$s` regs in 16-byte slots stored with `sd`** (almost every non-leaf function here:
  WaitDma, sceDmaRecv, PowerOffCB, sceGsSwapDBuff, all sceMc*/sceCd*/scePad*, fde_*, __throw ...).
  2.95.3-136 gives `sq s0,0x10; sd ra,0`; 2.96 gives 8-byte slots. gnu-reorder does not change this.
  (sceDmaRecv is otherwise easy: `WaitDma(d); d->qwc = 0; d->chcr.MOD = 1; d->chcr.DIR = 0; d->chcr.STR = 1;`
  with a D_CHCR bitfield struct.)
* `mult1` / constant multiplies done with `mult` (scePad*: `port*0x70 + slot*0x1C`) — neither compiler.
* frameless `j` sibcalls (mceGetInfoApdx, mceIntrReadFixAlign, cdvd_exit, __deregister_frame_info).

## IMPORTANT: gnu-reorder is the wrong model for libgcc / libm / libgraph (they use gcc reorg)
These objects have `beql/bnel`, delay slots filled **from the branch target** (`bne a0,v0,L; negu v0,a0`,
`b Lret; ld ra`) — that is gcc's reorg pass, which gnu-reorder turns off (-fno-delayed-branch).
But their **short single-block loops keep a `nop` in the backward-branch slot** and get GNU-as style
padding, e.g. litodp's normalise loop `dsll; addiu; daddu; sltu; nop; beqz; nop`.

Model that fits (verified, script: build/hand_wip/hyb_asm_experiment.py):
1. 2.95.3-136 `-O2 -G0` **with** delayed branches, `-S`;
2. for every backward branch whose loop body (label..branch) has no other branch/jump and <= 5 insns,
   and whose slot insn does not write a register the branch reads: move the slot insn back
   (before the insn that sets the branch's operand) and drop the noreorder block;
3. assemble with tools/gnu_reorder.assemble (2.96 GNU as, loop branches pinned).
Results: **litodp, floorf, __pack_d MATCH** (all three fail in both current modes), and all of
__fpcmp_parts_d, fptoui, dptoli, dptoul, __make_dp, __unpack_f, __pack_f, add_fdes,
old_find_exception_handler, cosf/sinf/tanf, _ch4dma, _decodeOrSkip, sceGsPutDrawEnv, func_002403D8,
func_00240AE0, sceDmaSync, kCopy*, kputs stay MATCH under it. Threshold evidence: litodp (4-insn body)
unfilled, decode_uleb128 (7-insn single-block body) filled; func_002403D8's loop slot is filled
from the fall-through (`move v0,0` writes the branch reg) and must stay.
Does not fit: libkernel memclr/kputchar/DIntr/sceSifSendCmd (truly -fno-delayed-branch, keep gnu-reorder),
InsertAlarm/snprintf_char/SetT2/s1_sceGsResetPath (match in SN mode, fail here — hand nops/asm or
SN-specific). => A toolchain mode `SLY2_ASM: gnu-reorg` implementing steps 1-3 would unlock
litodp/floorf/__pack_d now (wips are in build/hand_wip) and is likely the right mode for libgcc/libm/libgraph.

## Fresh integer division helper reconstruction (2026-10-13)

- `__udivdi3` (0x23C828, 372 instructions) and `__divdi3` (0x23B7F8, 443 instructions): complete new C drafts in `build/hand_wip/`, adapted from the [GCC 2.95.3 runtime source](https://raw.githubusercontent.com/gcc-mirror/gcc/releases/gcc-2.95.3/gcc/libgcc2.c) and [longlong.h](https://raw.githubusercontent.com/gcc-mirror/gcc/releases/gcc-2.95.3/gcc/longlong.h), with the GPL/runtime exception notices retained. The only hardware intrinsic is the original MIPS unsigned high/low multiplication; all division, normalization and correction control remains C. GCC 2.95.3-136, `-O2 -G0`, `gnu-reorg`; best positional differences are 243/372 unsigned and 437/443 signed. SN and GNU-db profiles do not improve the bodies.
- `__ll_B` must be `1L<<16`, not a 32-bit unsigned constant. On EE, that genuine 64-bit radix reproduces the native dsll32/dsll/dsra32 truncation chains in the quotient estimates. The independent 256-byte normalization tables at 0x2AAE18 (signed helper) and 0x2AB018 (unsigned helper) were checked against every index's bit length and are byte-identical.
- Unsigned entry and the first normalization/division block agree apart from the frame allocation and distant branch displacement. The target CSEs divisor halfwords across two expanded divide sites, uses a 0x10 local frame, and packs the quotient in four operations; ours reassigns those owners and packs through extra union partial-write masks. Genuine arithmetic packing, pointer-to-union packing, signedness, caller union lifetimes, -O3 and CSE flags were tried. A meaningful pointer packing helper obtains the native frame but introduces memory traffic, so it was not promoted. No unused frame padding, assembly substitutions or matcher changes were added. Signed normalization/negation has additional extraction and lifetime differences; neither draft is an exact match.
- Two genuine `_fpadd_parts` sign-field/exponent lifetimes both worsen to138/144; the existing complete103/144 GNU-reorg draft stays unchanged. No restrict/alias promise, artificial saved-register lifetime or new matching count is introduced. Closed evidence: sdk_worker/engine/sdk_fpadd_actual_sign_lifetimes.py.

- `fptodp` (23E290) retains its complete2/16 input-store/call-slot near-match. Seven bounded new genuine SWC1 input, retained address, input-record and address-only forms under documented GNU-reorg/SN profiles do not improve it: valid forms stay2/16 or worsen to3/16 and14/17. GCC prints the direct and full-GPR local-address DADDU operands as invalid memory syntax; no assembler rewrite is used. The actual LA address constraint reads no memory and remains3/16. No false dependency, volatility, extra storage, padding, fabricated return or profile change is retained. Closed ignored scripts: sdk_worker/engine/fptodp_actual_input_store.py, fptodp_actual_sn_store.py, fptodp_actual_destination_copy.py, fptodp_actual_full_address.py and fptodp_actual_object_address.py.

- Two further genuine float-input constructor/FP-parts member forms for `fptodp` retain its existing 2/16 scheduling near-match. No new ABI, memory operand rewrite, padding or source replacement is used. Closed ignored evidence: sdk_worker/engine/fptodp_actual_float_input_lifetimes.py.
