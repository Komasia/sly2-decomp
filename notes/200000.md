# Notes for 0x200000-0x210000

## KEY DISCOVERY: VU0 macro-mode code is matchable with the "j" asm constraint
ee-gcc 2.95.3-136 has a register class for the VU0 float registers: asm constraint **"j"** (TImode / qword values).
gcc then emits the qmtc2/qmfc2/lqc2/sqc2 moves itself and schedules them like the original:
```c
typedef int qword __attribute__((mode(TI)));
qword a = f(q), b = f(p), d;
__asm__("vsub.xyzw %0, %1, %2" : "=j"(d) : "j"(a), "j"(b));   // -> lqc2/qmtc2.ni/vsub/qmfc2.ni interleaved
```
(func_002046F0 matched this way; the earlier "skip VU0" advice for compiler-scheduled vf code is obsolete.)
Use `%0` etc. in the template (gcc prints `vf1`, the assembler accepts it). Constraints "b"/"y" are GPRs.

- Extracting VECTOR components from a qword in a GPR: `asm("mtc1 %1,%0" : "=f"(x) : "r"(q))` for x,
  `asm("prot3w %0,%1" : "=r"(y) : "r"(q))` (float output with "r" -> gcc adds mtc1) for y (func_002046B0).
