## Techniques that mattered here
- Brute-force permutation of store statements is cheap (~0.25 s per compile). Lines marked `//P` permuted by a tiny
  script (0x184268, 0x1848A8, 0x1829D8). Keep permutations <=120 per run (tool timeout 2 min).
- **Extracting a float from a qword returned in a GPR** (`pextuw a0,$zero,v0; mtc1 a0,f0`): inline asm accessor whose
  output is a *float* with "r" constraint, gcc adds the mtc1:
  `static __inline__ float GetZ(qword q) { float z; __asm__("pextuw %0, $0, %1" : "=r"(z) : "r"(q)); return z; }`
  (0x184510, 0x18A350). Probably works for prot3w/the "VECTOR returned in $v0" functions of 140000.md too.
- Clamp shapes: `static inline float GClamp(float g, float lo, float hi) { if (g < lo) return lo; if (g > hi) return hi; return g; }`
  with constants passed as args gives the hoisted-constant form (0x18F560, 0x187E88); in-place
  `if (t < 0) t = 0; else if (t > 1) t = 1;` gives the other form (0x181CB0). Reusing one float variable for two
  values fixed FP register allocation (0x181CB0 `x`).
- A time value loaded *before* a call and kept in $f20: assign it to a local first (`t = g_clock.t; x = t + f();`).
- dt read once per statement group: wrap the update in an inline taking dt as a parameter (0x181F60 Integrate()).
- Float compare operand order: `g_clock.t > pe->g2c` vs `pe->g2c < g_clock.t` changes load order/regs.
- `if (c) p->d = -1; else p->d = 1;` (not a ternary) gives `bc1t; addiu v0,-1 (delay); addiu v0,1; sw`.
- Stack slot order: a 16-byte-aligned `VEC` local got sp+0 and an int sp+0x10 like the target (a `qword` local didn't).
- `p->cv = f(); alloc(cv << 4)` reading the field back (instead of a local n) avoided an extra register copy (0x185150).
- Struct-copy of an 8-byte 4-aligned struct gives ldl/ldr/sdl/sdr (`struct K { int a, b; }`), save/restore around calls.
- Zero chains: `a = b = c = 0.0f` stores c,b,a; the last *store statement* of a run is rotated to the front.
- Inline `ClearX(px) { px->a = px->b = px->c = 0; }` reproduced `sw 4(v0); sw 8(v0); sw 0x210(a0)` (0x181268).
- Shared tail code (cross-jumping): write identical statements at the end of each branch (0x18A350, 0x187E88).
- Two different-case calls followed by the same test: `f = call(); goto test;` gives the shared `b test` (0x18D760 wip).
- C files are C89: no declarations after statements (compile errors show as the first output line).

### Techniques (VU0 code written with "j" asm operands, no register variables unless noted)
- **Pass call results straight into a small inline** (`VAdd(f1A62E8(p), func_0011E1A0(...))`, `GDist(f(a), f(b))`):
  gcc then spills the first qword exactly like the target (sq v0 -> lqc2, or qmtc2+sqc2 when the inline's asm
  needs a VF reg right away). Writing `a = f(); b = g(); asm(..a, b..)` gave s-reg copies instead (0x183540,
  0x183600, 0x1845A0, 0x182D78, 0x1843F0, 0x181478).
- Plain `qword` locals that only feed "j" asm operands get spilled to the stack (VF regs are call-clobbered) =
  the target's `sq v0, X(sp)` ... `lqc2 vfN, X(sp)` pattern (0x18ED98).
- **Scalar broadcast** `asm("qmtc2.ni %1, %0" : "=j"(s) : "r"(g)); u.q = s;` with a dead union store; a float
  field read as `"r"(*(int *)&p->g)` gives `lw` + qmtc2 (no lwc1/mfc1).
- **Loop-invariant asm hoisting**: a non-volatile qmtc2 asm with a plain qword output inside an inner loop is moved
  to the loop preheader (after the guard) like the target; a register-variable output is NOT hoisted (0x182810).
  `struct E *pe = &po->ae[i];` kept `lw 0x1DC(base)` instead of a folded `po+0x1DC` pointer.
- A `"memory"` clobber on a non-volatile asm (vsub) keeps a later field load below it while other insns still move
  (0x180EE8; volatile was too strong).
- "Normalize or default" (`if (len < 1e-4) n = K; else n = v * (1/len)` with `nop; nop; vdiv`): put the
  `nop\n\tnop\n\tvdiv Q, $vf0w, %2x\n\tvwaitq\n\tvmulq.xyzw %0, %1, Q` in one asm; when n is a spilled plain qword the
  then/else layout matches (0x183218). Output to a register variable `register qword rn __asm__("vf2")` fixed the
  vmulq output register. Length as an inline `VLen` (vmul / vaddw+vadday+vmaddz / vsqrt+vwaitq+vaddq asms).
- One-asm "vmul+vaddw+vadday+vmaddz" with `"=j"(d), "=&j"(one)` (d not early-clobber) let d reuse the input's reg
  (0x1828A8); `"=&j"` output on a matrix*vector asm gave a fresh VF reg (0x181060).
- vadda operand order: our `vadda.xyzw ACC, %1, $vf0` is what matches the target text `vadda ACC, vf0, vfN`
  (disassembler shows the fields swapped) (0x183818, 0x183218).
- Struct (MATRIX3) returning callee: `extern M3 *func_0011B340(M3 *pmOut, M3 *pm);` called as
  `func_0011B340(&m, &p->m)` fixed a $v0/$v1 choice for a later load (0x18E1E0). Temp+copy struct return
  (`m = f(...)` copying into another stack slot) needs .cpp (0x180EE8, 0x181060).
- **s-register priority from dtor call count**: func_00189EC8 (local `CLS` with out-of-line ctor/dtor 0x1AE478 /
  0x1AE4A0) had &cls / px in swapped s-regs until each exit path got its own `return 1;` (3 dtor calls before
  cross-jumping merges them -> &cls gets the higher allocation priority).
- func_0018EE38 matched first try: switch over 0x18D8 with jump table 0x2A6010 (even cases n+1, odd n, default
  `if (func_0018ED98(p)) n++`), `if (k < 2) { if (k >= 0) ... }` nested form, XY distance asm.
- Float params anywhere: func_001300B8 is `(void *, float, O *, float, void *, void *, M4 *, int)` (found by a
  script trying float positions, 0x18B348).
- `if (y > 0) {} else f = 0;` (with f = 1 before) reproduced `c.lt; bc1fl; f=0` (0x18ED98); inline
  `FClose(g) { int f = 1; if (g < K) {} else f = 0; return f; }` kept f out of an s-register (0x181478).

### Techniques / discoveries
- **sqrtf(0.5f) computed twice (no CSE), `c1 0x44` = sqrt.s $f1,$f0**: the target recomputes sqrt.s for each use, so it is
  not the gcc builtin. `static inline float sqrtf(float g) { float r; asm volatile("sqrt.s %0, %1" : "=&f"(r) : "f"(g)); return r; }`
  matched (non-early-clobber "=f" put the constant in $f1 and the result in $f0, wrong). spimdisasm prints EE sqrt.s as `c1 0x..`.
- Float zero-store chains (func_00187998): target 0x1070,0x1044,0x1040,0x103C,0x1078,0x1074 came from
  `x = y = u = 0; y2 = u2 = 0; x2 = 0;` (the lone last statement is the one rotated to the front).
- Range checks `8 <= d < 10` must be nested ifs (`if (d < 10) { if (d >= 8) ... }`) - `&&` gives addiu/sltiu.
- Inline `ClearX(px) { px->a = px->b = px->c = 0; }` again gave `sw 4(v1); sw 8(v1); sw 0(p+0x190)` (func_00188F20).
- Message handler switches: nested `switch` reproduces the beq/slti trees; `for (i = 0; i < 4; i++, pe++)` becomes the
  target's down-counting bgez loop (loop reversal).
- **One C variable reused for unrelated values** (UpdateJoy): gcc 2.95 has no web/live-range splitting, so a register
  holding fReady, then constant 2, then a pad-info result is ONE source variable (`x`); writing separate variables gives
  separate pseudos (different s-reg numbering). In the end fReady separate + `x` for (2, n) matched register numbering.
  A constant-copy `daddu s2,s1` (instead of `addiu s2,2`) came from `if (f() == 1) joys = x;` / ternary `? x : joyk`.
- Indexed array accesses (`aq[i-1], aq[i], av[i-1], av[i]`) instead of walking pointers let loop strength-reduction build
  the target's `s0 = p+0x18A0` / `lq -0x10(s0)` givs and keep init after the loop guard (func_0018BCE0 wip).
- A `qword` local whose address is passed gets its slot at first use; wrap it in a union to get the declaration-order slot.
- Callee float position again: func_00189C40 is (p, int, float, int, int, void *) (f12 load order).
- func_00183B80: s0/s1 swap fixed by giving the second qword call result its own block-scoped variable.

### Discoveries
- **Combined `vmul.xyz + vaddw/vadday/vmaddz` in ONE asm** (`"=&j"(d), "=&j"(one) : "j"(a)`) changed where the scheduler
  put an unrelated `lq` (the default-vector load for the `len < 1e-4` branch): with two asms the lq went between them,
  with one asm it lands after vmaddz like the target. Fixed the last diff of func_001830D8.
- Broadcast-scalar ordering: making the Bc() `qmtc2.ni` asm `__volatile__` kept `lw g; qmtc2` adjacent (volatile asm is a
  scheduling barrier for memory ops); an empty `__asm__ __volatile__("")` between two `lqc2` loads forced their order
  (`a = pos.q; asm volatile(""); b = pj->v240;`), and hard-reg vars `register qword a __asm__("vf2")`, `b ("vf3")` fixed
  the VF numbering. Put the dead broadcast-union store `u.q = s;` after the main asm (not inside Bc) to keep it late.
- `sqrt.s` in GetJoyXYDeflection is the asm-volatile `"=&f"` sqrtf (c1 0x10104 = sqrt.s $f4,$f1), not __builtin_sqrtf.
- **FP register numbering fixed by reusing ONE float variable for two unrelated values** (GetJoyXYDeflection): the loop's
  dot value `g` only got the target's $f4 (global allocation, longer live range) once the same variable `g` also held the
  sqrt length after the loop (`g = SqrtF(x*x + y*y); if (g > 1e-4f) *px = r*x/g; ...`), and the clamp result reused the
  per-iteration ratio variable `r`. 120 declaration-order permutations had no effect - only variable merging did.
  The `*pgDeflection = r;` store must come before the volatile sqrt asm.
- func_00185A80 (new, wip): loop structure needs the inner loops to re-load `pp->c` each iteration and not hoist `av[i]`:
  a `"memory"` clobber on the vaddw/vadday/vmaddz asm of the dot-product inline reproduces that (no clobber -> loop
  reversal + hoisting). Layout found: `qword f(void *, P *pp {int c; pad; qword av[6] at 0x10}, qword v)`,
  `float am[36] (sp+0), ab[6] (0x90), ax[6] (0xB0), union u (0xD0)`; am[i*c+j] = dot(av[i],av[j]) (int store via qmfc2),
  ab[i] = av[i].w + dot(v, av[i]); func_0011AD30(c, am, ab, ax, D_002A568C (float in f12)); v += av[i]*ax[i] (vadda/vmaddx
  with lw+qmtc2 broadcast). The broadcast union store is AFTER the 3rd loop in the target (only once) - looks like gcc's
  loop load_mems store-sinking; couldn't reproduce (inside loop -> sqc2 per iteration; after loop -> s spilled across the call).
