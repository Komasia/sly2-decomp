## Techniques that worked here
- **Pass-through arguments**: if a callee is reached with an untouched a1/a2, the caller forwards its own param.
  func_00211CA8 calls func_002128E8(p, k) with k = its own 2nd arg; declaring that fixed a v0/v1 swap that no
  rewrite could. Check which arg regs are live at each jal before blaming the allocator.
- **Iterated statement-order hill-climb** (move each statement to each position, take best, repeat) solved the
  long init functions func_00215AC0 (5 rounds) and func_00215BA8 (2 rounds + chained `p->x8 = p->xC = v`).
- Loop-invariant `p + 0x3038` hoisted into an s-reg by us but not the target: index through a cast
  `((B *)((char *)p + 0x3038))[i].first` keeps the offset in the load (func_002102A0).
- `struct E *e = &a->ae[l]; if (e->id == k)` vs `a->ae[l].id == k` swaps the addu operands (func_00213CD8).
- uchar param stored with sb: declare it `int` to avoid an `andi 0xFF` (func_00215960).
- Search loops over S{+0x80 ushort count, +0x84 A[0x30]} / A{ushort c, E *ae (0x18, id @0x14)} recur in
  func_002121E8/213928/213A08/213B00/213BD8/213CD8 - same source shape matched them all.
- **Real C++ constructor** fixed register naming that no C rewrite could (func_00211C58): declare
  `struct B { char pad[0xC]; B() __asm__("func_00212158"); virtual void f(); };`
  `struct D : B { ...; D() __asm__("func_00211C58"); virtual void f(); };` and define `D::D() { members... }`.
  gcc then sets the vptr itself and stores in the target's order/registers. `__asm__("name")` on member
  declarations renames ctors/methods so matchtool finds them.
- **Inline helper with arguments** fixes load order / registers of values that feed a loop: the target loaded
  `f->ay` then `f->c` into a0/a1 and copied to s-regs = args of an inlined function. Arguments are evaluated
  last-to-first, so `static inline void Upd(int n, Y *ay)` called as `Upd(p->af[i].c, p->af[i].ay)` matched
  (func_00217F38); `Draw(p, p->pq->af[i].c, p->pq->af[i].ay, a)` with a count-down loop matched func_0021A998.
- **RGBA (4-byte colour) class**: `struct RGBA { unsigned int u; RGBA(unsigned int x) { u = x; } }` -
  `RGBA(0xFFFFFFFF)` gives the target's `lui 0xFFFF; ori 0xFFFF` (a plain int -1 gives addiu). With
  `__attribute__((aligned(16)))` locals/temps get the 0x10-spaced stack slots (func_00217C20). By-value RGBA
  params with a copy ctor `RGBA(const RGBA &c) { *(RGBA2 *)this = *(const RGBA2 *)&c; }` (RGBA2 = 4 uchar)
  reproduce the lwl/lwr/swl/swr copies to stack temps (func_00217CA8 matched first try).
- Statement-order sweeps: tiny script that moves each statement between `//{` `//}` markers to every
  position and runs matchtool (2-3 rounds solved func_0021F2E0 and func_002156B8 store orders).
- `for (; FDigit(*pch); pch++) { n = n * 10 + (*pch - '0'); }` with `static inline int FDigit(unsigned char)`
  re-reads *pch like the target (CchParsePchzInt); pointer must be `unsigned char *` for lbu.
- Two-case switch emitted as `==1, <2, ==0` needs an extra empty `case 2: break;` (FNegTftUl).
- `max.s f20, f21, f20`: write `fMax = (fMax > fCur) ? fMax : fCur` (func_002161C8).
- Soft-float double code (ExpFirstFromG): `if (g > 0.0) {...} else { exp = 0; }` with a single exp variable;
  libgcc calls are masked so any comparison libcall matches.
- Two-entry `if/else if` on p->k gave wrong layout; `switch (p->k) { case 4: ...; case 6: ... }` matched (func_002158C0).
- Compare operand order: `k == p->a[i].id` vs `p->a[i].id == k` swaps beq operands (func_00217BA0).

### Techniques / discoveries
- **Callee return type again**: func_00210BE0's alloc-init call `func_00116A98(&al, ...)` had to return a pointer
  (ALLOC *) - fixed a v0/v1 swap in the loop guard that no loop rewrite touched.
- **Pass-through arg fixed a "missing daddu a0,s1"**: func_00212298 calls func_001A5C28(p, pbis) (base-class
  load with the stream still in a1). Declaring it 1-arg let gcc keep p in a0 and changed the stores.
- **Constant stores come out in REVERSE source order** when they precede a call (func_00212298: x78,x74,x70 in the
  target = source x70,x74,x78). A single-move sweep can't find a reversal - try pairwise swaps / full perms.
- `p->x60 = 1; f(p);` (store before the call) is what puts the store into the jal delay slot (func_00215D40).
- min.s/max.s operand order: `GMin(a,b) { return b < a ? b : a; }` gives `min.s d, a, b`; `a < b ? a : b` swaps them.
  `max(0,g)` as `0 < g ? g : 0`-style: use `a < b ? b : a` for `max.s d, a, b`.
- `x * k1 * k2` gets folded by -ffast-math; to keep two muls put the first product in its own statement
  (func_002123C8). Its div was also scheduled first only when `h = (x << 9) / 640;` came before the float temp.
- Loop over `Y *ay` with `y = &ay[i]` inside the body (not a walked pointer) puts the pointer copy after the
  `blez c` guard like the target (func_00213E20). Also `c = h->c; ay = h->ay;` order for loading into t2/s3.
- Tagged-flag word `v = msg.grf; if ((v ^ 1) & 1) {...; msg.grf = v | 1;}` also fixed an s-reg swap (func_00210538).
- `int l = -1;` declared in the loop body *before* `if (k == e->id)` put the -1 into the bne delay slot (func_00212E40).
- WriteTftPchz: padding loops are a static inline `WritePad(postrm, ch, c)` with a local `char b = ch`; the
  zero-inits of cchLeft/cchRight must come *after* the `if (!pchz)` default (they land in the strlen delay slot);
  `int cchPad = width - cch;` shared by both branches. D_002A9370 = "(null)" probably.
- Lowest-address relocated constants (`lui 0; addiu 0xC0`) = extern symbols at tiny addresses (VU microcode
  addresses), e.g. `extern char D_000000C0[]` (func_00211A80).
- func_00210CF0 = __static_initialization_and_destruction_0 (prio 0xFFFF): ctor func_0020D9D0(&D_003DD490), object
  D_003E1C20 {0, vt D_002C3EB8, 0, D_003E1C60}, six pool-refcount inits func_0011CCA8(pool, cb, c, 0x10), dtor
  func_00258348(&D_003DD490, 2).
