## Techniques found useful here
- 128-bit by-value args (por/sq of $a2/$a3): use `typedef int qword __attribute__((mode(TI)));`.
- Pass-through arguments: if a caller's extra arg registers are untouched before a call,
  pass them to the callee (changes prologue scheduling), e.g. func_00144338.
- `x in {2,3}` style tests compiled as two slti branches come from `switch` with case labels.
- Return type int vs void of callee changes scheduling of arg moves (func_0014C6A0).

- Accessing a field of a global struct: declare `extern struct G g;` and use `g.field` - gives
  `lui; addiu base; lw off(base)` (unfolded); `((char*)&g)+off` folds into the relocation instead.
- A stack `sd` of an asm result that is otherwise kept in a register: asm output into `ulong c[2]` array local.
- Virtual calls: `struct VTE { short d; short pad; void (*pfn)(); }; e = &o->vt[N]; e->pfn(o + e->d, ...)`.
  Use a fresh block-scoped obj/entry temp for a second vcall (register choice).
- Sorting comparator returning `a - b` pointer difference: divide by sizeof shows as mult 0x38E38E39 + sra.

- Loop that must stay non-rotated with invariants hoisted: `do { ...; if (x) break; ... } while (1);`
  (func_0014BC78); `for(;;)`/`while(cond)` got rotated, goto-loops lose invariant hoisting.
- A slt+xori bool test comes from a named flag: `int fDone = a >= b; if (!fDone) ...` (func_0014BF48).
- A pointer held in an s-register for a local array: declare `char *pch = ach;` at function scope (CdPath).
- Shared tail stores of a float from several branches: compute into a local and store once.

### Discoveries
- **`extern const struct K D_xxx;`** for an 8-byte rodata struct passed by value (ldl/ldr into a2) lets the scheduler hoist the
  ldl/ldr above a preceding store (`p->x2F8 = oid; f(&g, p, K, 0)` -> lui/sw/ldl/ldr order) - fixed func_00148C98.
  Non-const extern keeps the store first. Probably useful wherever a rodata load must move past a store.
- Rodata floats (0x2A4xxx) loaded with lwc1 are literals (FLT_MAX at 0x2A4B08/0x2A4D64/0x2A4EC4/0x2A4FF0/0x2A4FF4):
  writing the literal instead of an extern changed scheduling enough to match func_0013A9E8 (notes/130000).
- AREQ built through a pointer (`struct AREQ *preq = &req; preq->cb = ..; other store; preq->cbAlign = 0x10; f(preq)`)
  gives the `addiu a1, sp, X` ... `sw v1, 4(a1)` form (func_001400B8, func_0014C9F8). Same in func_00149440 for the CTX:
  passing `&ctx` directly to ctor and dtor gave `addiu a0,sp; daddu fp,a0`.
- `m[0] = m[5] = m[10] = m[15] = 1.0f` (identity diagonal after memset) gives the target store order 0,3C,28,14; and
  `g.cid++; p->pso->id = g.cid;` (not `= ++g.cid`) for the increment-then-reload order (func_001400B8).
- Index-of-other-end pattern `ae[1 - i]` with `i = IOther(...)` static inline (`a == b ? 0 : 1`), plus `int j = 1 - i;`
  and `struct E *pe = &pso->ae[i];` for the operand order (func_00148C98, func_00144640).
- `if (k >= 2) return; if (k < 0) return;` keeps slti+bltz (instead of sltiu) (func_00144640).
- A shared "found" block placed *before* a search loop in the target: put a label in the switch before the case
  (`case 3: ...; break; found: ...; break; case 0: loops { if (..) goto found; }`) (func_00148C98).
- Memcpy (func_001AE5A0) result unused: declare it `void` - fixed 3 v0/v1 diffs after calls in func_00149440.
- Store-order: `pv->x = pv->y = pv->z = 0` through `struct V3 *pv = &px->v190` gave `addiu v0, a0, 0x190; sw 4(v0);
  sw 8(v0); sw 0x190(a0)` (func_0014AE38); scripted permutation of the three scalar stores fixed the rest.
- case-2 tail of func_0014AE38 is cross-jumped with case 4 (same vcall slot 8 on po) - write the vcall in both.
