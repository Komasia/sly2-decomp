## Techniques
- Pass-through args: when a callee arg reg is live in the target, add the arg (func_00151648: s-reg choice
  only matched when the 3rd param was passed on to func_0014FCC8).
- Loop find returning element pointer with two parallel givs: `struct E *pe = &p->a[i]; if (pe->id == x) return pe;`
  inside the loop body (func_00154180).
- Return-1-in-switch: `case 0: case 1: if (c == 0) return 1;` then `return 0` (FPausedEmitter).

- **Returning a VECTOR (qword) through a stack temp** matched with a union: `union {qword q; float f[4];} v;
  v.q = f(); v.f[2] += 150.0f; return v.q;` (func_00150780).
- Vector components from a TImode reg: X = `asm("mtc1 %1,%0" : "=f"(x) : "r"(q))`, Y = prot3w, Z = `pextuw %0,$0,%1`
  (see build/hand_wip/func_00150F58.c).
- Float min/max: `static inline float GMin(float a, float b) { return a < b ? a : b; }` and argument order controls
  min.s operand order (func_00156898, DxMaxLine).
- `if (f) k = x - 1; else k = x;` keeps the branch where `k = x; if (f) k--;` becomes movn (func_0015DA88).
- Re-reading a field instead of caching it in a local (`p->c280` twice) avoided early int->float conversion (func_00153760).
- A call nested in a call's argument list makes gcc pre-evaluate the other args (e.g. a format-string address into an
  s-reg); compute the inner call into a local first (func_0015D8F8/0015D9C0).
- Switch case order matters for cse: `case 0:` before `case -1:` let gcc reuse $a0 (SetEmitterParticleCount).
- Nested struct loop: `struct E *pe = &p->a[i];` then `pe->ar[j].x` in inner loop picked the target giv (func_00152578).
- `func_0015EF30` matched only with the array element read into a local before the call.
- Store order: source F4,F0,118 / FC,F8,148 gave target 118,F4,F0,F8,148,FC (func_001591B0) - permute when stuck.

### Techniques (new)
- **Float parameters can sit anywhere in the signature**: a virtual call whose float arg is computed by a call and whose
  int arg is loaded after that call => declare the method as `(qword, float, int)` and pass args in that order (func_0015B1B0).
  Same trick as round 3 but for evaluation order, not register numbering.
- RGBA (4 x uchar) temporaries that must live in memory (sb into a stack slot instead of dsll/or packing): compile as .cpp and
  give RGBA an empty ctor `RGBA() {}` (func_0015DD48). Stack-slot order then follows: function locals in declaration order,
  inline-param copies / inline locals, then later `BUF buf;` declared after the inline call (C++ mid-block declaration).
- A pointer local (`BUF *pbuf = &buf;`) gives the target's s-reg holding a stack address used by two calls.
- A loop whose test contains a call is not rotated: `for (i = 0; i < c && (p = f()) != 0; i++)` reproduces `b test` entry.
- Hoisted-memory copies: when the target compares a loop value against a register *copy* of something (a1 = a3 copy),
  compare against the memory expression (`*pips`, `l.cplo`, `pe->plo`) inside the loop; loop.c hoists it into a new pseudo
  (func_0015E3E8, func_0015E678).
- Read jump-table targets before guessing case semantics: in func_0015DD48 the k==0 case stored 1 and k==1 stored 0xE.
- Store `t = a[i-1]` via `aiFirst[i] = t = ac[i-1]` fixed giv register order (func_00157AE0); separate block-scoped loop
  counters per loop fixed the rest.
- Two partially overlapping MATRIX4 copies: `MATRIX4 *pm = &p->m; m = *pm;` gives the target's base-register form.

### Techniques (new)
- VU inline asm: `"=&j"` (early clobber) on vsub output gave the target's distinct dest register (vf1 = vf2 - vf3).
- Two independent VU asm statements (vmini then vmax) are emitted in REVERSE source order relative to each other in a loop
  body; write vmini first to get vmax first (func_001545F0). `"+j"` in-place form reproduced the loop-top spills.
- Loop `for (i = 0; (f = i < 1); i++) if (!g()) break; return !f;` (bool f) gives non-rotated `slti s1` test + `xori` return.
- vmulax/vmadday/vmaddz matrix*vector: list the vector operand first in the asm inputs ("j"(v), row0, row1, row2) to get the
  target's vf2=v, vf4/vf3/vf1 = rows (ChooseEmitVelocity). `int iTilt = i / c; int iPan = i % c;` temps fixed FPU load order.
- Return-path layout: `if (c) { big VU path; return r; } return f(x);` kept the two `jal; b epilogue` tails separate where
  `if (!c) return f(x);` let gcc cross-jump/reorder them (func_00153E60).
- `float t = clock.t; t = t - f();` makes the clock load happen before the call into f20 (func_0015B0C8, func_00155AE0).
- In-loop float -> VU: target `lw v0, 0xC(a1); qmtc2` (no FPU) = asm "r" input taking the float field directly from memory.
