# Notes for 0x1F0000-0x200000

## Techniques
- VU0 cross product (vopmula/vopmsub pair) matched as ONE asm statement with "j" operands:
  `asm("vopmula.xyz $ACC, %1, %2\n\tvopmsub.xyz %0, %2, %1" : "=j"(c) : "j"(a), "j"(b));` (func_001FAB48).
- Unexplained 0x10 stack frame in a leaf list-search: unused `int unused[4];` (func_001F6788/67E0).
- C++ `if (pa) px = new X(pa, pb); else px = 0; return px;` with class operator new (func_001FCCF0 =
  pool alloc from D_003DD074) and out-of-line ctor (func_001FC190) matched func_001FC138; `if (pa) return new..; return 0;`
  and C forms didn't (block order).
- 1-bit ulong bitfield compared with a param: declare the param `long` to avoid the dsll32/dsra32 sign extension
  (func_001F7F48). Testing bit 34 via `fl & (1L << 34)` (no bitfield) when target uses an and-mask (func_001F2798).
- Callee register args that look "unset" (e.g. $a2 still holding a loaded pointer) = pass that value as an extra arg
  (func_001F3C10 -> func_001A4478(&g, 0, pq)).

- Store order: gcc rotates the LAST store of a run to the front; brute-force permutations of the store statements
  (func_001F8BF0: target q,n,x,y,z,r came from source n,x,y,z,r,q).
- ulong flag tests without the int truncation (dsll32/dsra32): use early returns `if (!(fl & M)) return;` (func_001F4BA8);
  for a 1-bit ulong bitfield read via dsrl32+andi, copy it into a local first (`bool f = pa->b60; if (f)`), .cpp (func_001F2A60).
- RAII: a pointer stored to the stack across calls (`sw s0,0(sp)` ... `lw a1,0(sp)` before a vcall) = C++ local object
  with inline ctor/dtor doing vcalls (Lock l(p): ctor slot1, dtor slot2) (func_001F1078).
- `int f = 0; if (!p->n40) { f = a || b; f ^= 1; } if (f)` reproduces the xori-1 in delay slots (func_001FC270).
- `(A || B) && C` materialized with `daddu v1,v0; bnez v1; li v0,1; li v0,0` = `if (cond) return 1; return 0;` (func_001F4FC8).
- func_00130D30(obj, int k, float, float) - check callee arg regs (f12/f13 live) (func_001F08D0).

- Unaligned `ldl/ldr` of a global into an arg register = an 8-byte struct {int,int} passed BY VALUE (func_001F4F10,
  D_002A8278 passed to func_00149AB8(&D_003DD490, obj, S8, 0)).
- Two identical calls cross-jumped into one by gcc: restructure as if/else-if with `break` inside the loop (func_001F4F10).
- A struct returned via hidden pointer and then block-copied (lq/sq x3) before passing by pointer: write
  `struct M3 c, t; f(&t, ...); c = t; g(&c);` (func_001F8AD8).
- Index-into-stack `a[c-1]` where gcc folds the -1 into the offset of the count field: `*(s.a + s.c - 1)` (func_001FE3F8);
  `s.a[s.c - 1]` doesn't fold.
- Inline `Norm(deg) { n = deg % 360; return n > -1 ? n : n + 360; }` fixed reg alloc (func_001FC380).
- Void-returning vcall uses v0=vt,v1=fn; int-returning vcall loads into a1/v0 or v1/v0 - match the fn pointer type.

- **Real C++ virtual calls**: when the target keeps `&vt->entry` in an $s reg across another call (lw 0x4($s0) for the fn),
  write an actual C++ class hierarchy: `class B { int a,b,c; virtual void v1(); ... }` (vptr at +0xC, dummy virtuals to
  reach the slot) and `class X : public B { data... }` so derived data doesn't push the vptr (func_001F49C8).
- Lock pattern used all over 0x1F0xxx (sound/anim object): `struct Lock { P *p; Lock(P*) {vslot1} ~Lock() {vslot2} };`
  (func_001F0850/0948/0FD8/1078/10F0).
- func_0011D948(&D_002BBB60, float) -> float; callers compare `(int)(x*1024)` (func_001FB1F8/FE9F8/FC2E0).

- Globals in 0x3DD490..0x3E5xxx are fields of the big game-state struct D_003DD490; access them as
  `D_003DD490.field` (not a separate extern) - it changes scheduling around stores (func_001F8668: D_003DD490+0x3E5C).
- `ape[n++] = pe` (giv) vs `*ape++ = pe` changes where the pointer copy is made (func_001F7E08).

- Ref smart pointer (func_001FE310): `struct Ref { X *px; ~Ref() { if (px) px->vslot2(); } }` in .cpp; the dtor
  re-check after a null test (`beql px,0 -> lw a1,0(sp)`) only appears with a real C++ dtor. func_00259B48(&ref, X*) = assign.
- Tagged flags getter not solved: func_001F3B28 (wip) - target recomputes the `xori/andi` tag test in each inline
  instead of CSE-ing it.

- **VECTOR component extraction from a qword in a GPR** (solves the prot3w/pextuw pattern):
  `static inline float X(qword q){float f; asm("mtc1 %1, %0":"=f"(f):"r"(q)); return f;}`,
  Y: `asm("prot3w %0, %1":"=r"(f):"r"(q))`, Z: `asm("pextuw %0, $0, %1":"=r"(f):"r"(q))`; then
  `FNear(a,b) = func_0011D4D0(X(a),X(b),0.0001f) && ...Y... && ...Z...` (func_0011D4D0 = FFloatsNear) (func_001FB2F8/FB3F0).
- A `return` inside a C++ Lock scope duplicates the unlock vcall + `b epilogue` (func_001F09D8).

- VU0 length^2: `asm("vmul.xyz %0, %2, %2\n\tvaddw.x %1, $vf0, $vf0w\n\tvadday.x $ACC, %0, %0y\n\tvmaddz.x %0, %1, %0z"
  : "=j"(d), "=&j"(one) : "0"(d))` then qmfc2/mtc1 asm; tie with "0" (not "=&j" + "j") to reuse the reg (func_001F72F8).
  Float compare materialized via `bc1fl; daddu v1,0`: `{ int f = d2 < r2; if (f) return 1; }`.
- Declaring a callee as returning int even though the result is unused fixed a v0/v1 choice (func_001F7410).
